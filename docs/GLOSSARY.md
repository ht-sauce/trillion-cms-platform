# 术语表 · trillion-cms-platform

> 本文件是项目**专有名词的统一解释口径**：文档、后台界面、日常沟通里出现这些词时，含义以本表为准。
>
> 两个来源，各有分工：
> - **界面文案**（后台标签与问号提示）唯一事实来源：`apps/admin/app/config/glossary.ts`——页面上不硬编码名词，一律从那里取值；
> - **本文件**：面向读文档的人，比界面提示更详细，并标注名词出现的文档位置。
>
> 新增名词时两边同步：先加 `glossary.ts`（界面要用就先在那里），再补本表一行。
>
> 使用范围：`AGENTS.md`、`docs/REQUIREMENTS.md`、`docs/spec/**`、`docs/PROJECT_STRUCTURE.md` 中出现这些名词时，均视为本表定义。

## 1. 地址与域名

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **站点前缀（slug）** | 站点在地址里的一段英文标识（如 `example-site`）。本地多站点共用同一端口时靠它区分站点，同时是 SSG 产物目录名。上线后改动会让地址失效 | spec/03、spec/09 §6.2 |
| **主域名（domain）** | 站点的唯一规范访问地址。canonical、sitemap、llms.txt 里的绝对地址都用它 | spec/04、spec/06 |
| **别名域名（domains）** | 指向同一站点的其他域名（`www.` 写法、历史域名、备案备用域名）；只用于访问，不作规范地址 | ADR-022 |
| **物化路径（path）** | 目录/页面在数据库里**存下来的完整地址**（`Channel.path` / `Page.path`），不是每次由父子关系临时推导；首页为 `/`，目录索引页等于该目录地址 | spec/04、ADR-025 |
| **URL 片段（slug 字段）** | 页面地址里属于该页的那一段英文；页面发布后锁定，改不动（服务端 400） | spec/03、ADR-025 |
| **访问地址** | `主域名 + 站点前缀 + 物化路径` 拼出的完整可访问网址，唯一拼装实现是 `buildSiteUrl` | ADR-031 |
| **canonical** | 告诉搜索引擎「这一页的规范地址是哪个」，用于合并重复内容；同站点同地址不允许出现两个 | spec/06、spec/10.1（见 09 §10） |

## 2. 内容与编辑器

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **内容树** | 编辑器左列按「目录 → 页面 → 页面引用的块」组织的层级视图；**只用于后台管理，不驱动站点导航** | spec/09 §6.2、ADR-029 |
| **页面类型（kind）** | `static` 静态页 / `list` 列表页（汇总所在目录的子页面）/ `detail` 详情页 | spec/09 §4.4 |
| **草稿（draft）** | 只存在后台、不影响线上的整页内容快照；后写覆盖、不构建 | spec/09 §3.2 |
| **三态** | 草稿（后台）→ 预览（读草稿的临时访问）→ 发布（生成线上产物），三者互相独立 | spec/09 §6.3 |
| **编审信息** | 医疗类内容的合规字段（撰稿人 / 审核医师 / 来源 / 下次复核日期），缺失即阻断发布 | spec/09 §10.4 |
| **JSON-LD** | 注入页面的结构化数据（页面是什么、机构是谁）；支持「自动 + 追加」与「全量覆盖」双模式 | spec/09 §10.3 |
| **结构化 Block（块）** | 页面正文由若干「块」按顺序拼装（标题 / 卡片 / FAQ / 图集 …），每块有自己的一组字段；改内容 = 填各块的字段值 | spec/09 §3.1、§4 |

## 3. 块（Block）

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **块代码化** | 块 = 数据库里存的 Vue SFC（模板 + 脚本 + 样式），后台在线编辑、服务端编译校验 | spec/09 §4、ADR-024 |
| **块标识（key）** | 块在代码里的英文名（如 `hero-dark`）；同站点同标识只有一份代码 | spec/09 §4.1 |
| **字段声明** | 块代码内用 `defineBlock({ fields })` 声明可填字段，后台据此自动生成数据表单 | spec/09 §4.1 |
| **块实例（instance）** | 页面上「这一个块」：同一块代码可在一页出现多次，各有独立数据（`{ id, key, enabled, data }`） | spec/09 §3.1 |
| **本站块** | 已复制到本站、本站独有的块代码，改动只影响本站 | ADR-035 |
| **公共模板（公共块）** | 平台模板库里的初始实现（`siteId = 0`），**不再是站点的渲染来源**；站点首次引用时复制一份到本站 | ADR-035 |
| **块隔离** | 站点之间不共享块代码：引用即复制副本，模板改动只影响之后新引入的站点 | ADR-035、spec/09 §4.5 |
| **代码指纹（codeHash）** | 块代码的校验码；代码变则用到它的页面自动进入「待发布」 | spec/09 §8.2 |
| **使用位置** | 某块被哪些页面引用、引用几次、是否启用；改代码前的影响面参考 | spec/09 §6.1 |

## 4. 发布与产物

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **发布** | 生成并上线页面产物；粒度只有「单页 / 整站」，一期不做块级发布 | spec/09 §8.3 |
| **增量发布** | 只重新生成「有改动、还没发布」的页面（未改动页不动） | spec/09 §6.3 |
| **整站重建** | 该站点全部页面重新渲染并重建索引产物，不管内容有没有改动；用于产物缺失、结构升级或大批页面重出 | spec/09 §8.3 |
| **构建状态** | 站点最近一次发布的进度：未构建 / 排队中 / 构建中 / 构建成功 / 构建失败。进行中不允许再次发起构建（按钮锁定，手动入口返回 409），**构建失败不影响线上旧产物** | spec/06 §1.1 |
| **GEO 索引更新**（接口 `POST /publish/repair`） | 只重出站点根目录的索引文件（robots.txt / sitemap.xml / llms.txt 与产物清单路由），不重新渲染页面；改了站点配置而页面内容没动时用。旧称「产物修复」 | spec/09 §8.4 |
| **内容指纹（contentHash）** | 页面内容的校验码。与线上那次发布的指纹不一致 → 该页有未发布改动 | spec/09 §8.2 |
| **发布状态徽标** | 已发布 / 待发布 / 产物缺失 三态，由内容指纹与产物清单派生 | spec/09 §8.2 |
| **产物清单（`_trillion.json`）** | 记录「页面 ↔ 线上文件 ↔ 指纹」的清单，是页面与线上产物对应关系的**唯一事实来源** | spec/09 §8.2、ADR-033 |
| **回退上一版** | 用上一版产物覆盖线上并更新清单（**不回退数据库内容**）；回退后该页显示「待发布」 | spec/09 §8.4 |
| **站点下载** | 把线上产物打包下载：`完整包` 可直接托管 / `纯静态包` 仅 HTML（CDN 回源） | spec/09 §8.5、ADR-030 |
| **分包模式** | 下载产物时的两种打包方式：完整包（含客户端资源，解压即可托管）/ 纯静态包（只含 HTML，供已有站点做 CDN 回源同步） | spec/09 §8.5 |
| **构建缓存** | `blockHash + appHash + apiBase` 三元组命中时跳过 Vite 构建，发布开销降为「按目标页 SSR 爬取」 | ADR-032 |

## 5. GEO 与合规

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **GEO** | 生成式引擎优化：让 AI 引擎（对话式搜索）能读懂并引用站点内容，与 SEO 并重 | spec/00、spec/06 |
| **GEO 分层** | 块只输出语义化结构与块标识；页面负责 JSON-LD / canonical / 标题描述；站点负责机构实体声明 / llms.txt / robots | spec/09 §2 |
| **GEO 体检 / GEO 分** | 按 GEO 规则给页面打分并列出问题；分数只作提示，不阻断发布 | spec/09 §10.4 |
| **机构实体档案（`/entity`）** | 声明「我们是谁」的那一页；机构信息**全站只在这里完整定义**，其他页只引用 `@id` | spec/09 §10.2 |
| **NAP** | 名称（Name）/ 地址（Address）/ 电话（Phone）的对外统一口径；三处不一致会被判可信度不足 | spec/09 §10.4 |
| **llms.txt** | 站点根目录给 AI 爬虫读的纯文本说明；随发布自动重新生成 | spec/06、spec/09 §10.1 |
| **AI 爬虫** | 代表 AI 引擎抓取内容的程序（GPTBot / ClaudeBot / Bytespider 等）；后台「GEO 监控」统计其抓取分布 | spec/06 |
| **AI 爬虫策略** | 站点 `robots.txt` 里对 AI 爬虫的放行 / 禁用规则（默认放行全部已知 AI 爬虫，站点级可覆盖）；放行才有机会被引用 | spec/06、spec/09 §10.1 |
| **GEO 双模式** | `自动 + 追加` = 系统结果保留、只把你写的内容补在后面；`全量覆盖` = 完全用你写的内容替换系统生成的部分 | spec/09 §10.3 |

## 6. 工程与运行

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **SSG / SSR** | 静态生成（内容改动后重生成文件，本期形态）/ 服务端实时渲染（`renderMode` 字段保留、后台不暴露切换） | ADR-019、spec/03 |
| **预览票据（ticket）** | 后台为「预览草稿」签发的一次性通行证：短时效、只读单页草稿、不能触发构建、页面不被收录 | spec/09 §7.5 |
| **预览模式** | 带票据打开站点的浏览状态（只读 + noindex + 关埋点），提示由后台画布头部展示 | spec/09 §7.5 |
| **站点级 / 平台级** | 权限分层：站点级只能操作被授权的站点；平台级可跨站点与维护系统设置 | spec/05 §鉴权矩阵 |
| **JWT-A / JWT-M** | 两套互不通用 token：`JWT-A` 管理后台、`JWT-M` 站点会员（密钥隔离） | spec/05 |
| **统一响应结构** | 所有接口返回 `{ code, message, data }`，由服务端 `TransformInterceptor` 产出 | spec/05、AGENTS §7 |
| **代码上线 / 数据库上线** | 两条独立命令：`release:*` 只发代码（绝不改库）；`db:deploy*` 是唯一改结构入口 | ADR-034、spec/07 |
| **开发 / 上线三条命令族** | `allDev*`（源码直跑）/ `release:*`（构建 + 生产模式启动）/ `db:deploy*`（迁移）三者不混用 | AGENTS §9、spec/07 §3.5 |
| **接口基址** | 后台调用服务端接口的根地址（由根目录 `env/` 派生后注入，前端不写死） | spec/03 §2.2 |
| **时区** | 全平台统一的时间口径（服务端按中国时区格式化业务时间，不随服务器/浏览器时区变化） | AGENTS §5 |
| **静态资源** | 图片、附件等文件的存放位置（服务端 `uploads/`）与对外访问前缀 | spec/02 |
| **原位替换** | 替换素材库文件（`PUT /files/:id/replace`）时保持记录与访问 URL 不变、仅覆盖物理文件（新文件 MIME 必须与原记录一致）；站点里已引用的地址无需改动、无需重发站点，替换即全站生效 | spec/05 §3.3 |
| **PV / UV** | PV = 页面浏览量（每次打开都算）；UV = 独立访客数（同一人当天只算一次） | spec/06 |
| **发布任务** | 一次发布动作的排队记录（类型 / 状态 / 时间）；同一站点的任务串行执行 | spec/09 §8、ADR-032 |
| **热门路由** | 按访问量排出的页面前几名（“路由”即页面地址），用于判断哪些内容最受关注 | spec/06 |

## 7. 导航配置

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **导航管理** | 配置站点头部主导航与页脚四列的入口；导航是**独立配置**的数据，不随内容树自动变化 | ADR-029 |
| **导航分组** | 头部主导航（`header`）与页脚四列（`footer-1`~`footer-4`）共五组；分组内顺序即页面展示顺序 | spec/09 §3.4 |
| **站内页面** | 导航项从本站已有页面里选跳转目标（推荐：站内跳转与预览票据都能正确保持） | spec/09 §3.4 |
| **外部链接** | 导航项指向站外网址；不会随站点前缀 / 预览票据改写 | spec/09 §3.4 |

## 8. 权限与后台

| 名词 | 含义 | 相关文档 |
| --- | --- | --- |
| **平台级** | 角色标记：可跨站点操作，并维护站点管理、系统设置、角色与用户 | ADR-019 |
| **站点授权** | 把后台账号限定在指定站点（平台级角色等于全部站点） | spec/05、spec/03 §2.2 |
| **授权菜单** | 角色能看到的侧栏入口；**父菜单未授权时子菜单会被一并隐藏** | ADR-018 |
| **路由路径** | 后台页面的地址（如 `/blocks`）；目录型菜单留空，在侧栏只负责展开子菜单、不可点击 | spec/03 §2.2 |

## 9. 维护约定

- 名词在**界面**上出现时：从 `apps/admin/app/config/glossary.ts` 取值，并用 `TermHint.vue` 出问号说明（页面里禁止硬编码名词与解释）
- 名词在**文档**里出现时：含义以本表为准；新增名词请在本表补一行（标注相关文档），顺手在首次出现的文档处加一句链接
- 名词**改名**时：先改 `glossary.ts`，再全局搜索本表与文档，保持两处一致
